# Feature Contract v1

contract_id: feature_contract.v1
schema_version: v1
artifact_class: feature_contract
producer: moex_features
consumer: strategies / moex_research.runners / moex_backtest.engine

## purpose

Declares feature inputs and availability semantics for anti-leakage-safe strategy tests.

## required_fields

- feature_ref_id
- feature_id
- schema_version
- artifact_class
- producer
- consumer
- dataset_refs
- feature_columns
- calculation_window
- warmup_or_min_history
- known_by_when
- input_availability_rule
- anti_leakage_invariants
- null_handling_rule

## validation_rules

- feature_ref_id must be unique within the strategy test manifest.
- dataset_refs must point to dataset_reference_contract entries.
- feature_columns must be explicit and non-empty.
- calculation_window must specify whether current-bar data is allowed.
- warmup_or_min_history must be explicit when rolling features are used.
- known_by_when must state the earliest decision time at which each feature is valid.
- input_availability_rule must distinguish prior-session, current-session, and post-close availability.
- anti_leakage_invariants must prohibit future-dependent inputs.

## forbidden_patterns

- Feature computation that reads future bars, future labels, or final outcome windows.
- Hidden D-day data use for D-day ex-ante decisions unless explicitly allowed by known_by_when.
- Implicit joins by nearest timestamp without declared calendar/session semantics.
- Ad hoc feature columns generated by research scripts without contract registration.
